# Agent Note: 鱼形标记以游动承担首屏与历史加载态

Status: implemented

[English](2026-10-06-fish-swim-loading-mark.md) | 中文

## Problem

会话首屏的鱼形标记只在指针悬停时游动，于是产品唯一自带动效的图形，恰恰在最需要「还活着」信号的界面上静止不动：空白草稿首屏、`settling` 相位（会话正在回放历史，外壳还无法判断该显示首屏还是停靠式输入区，因此整列是空的），以及聊天视图的历史回放提示。这些界面要么只有一行文字，要么什么都没有。游动的几何数据——轮廓的两帧加权形变——原本放在 `ui-conversation` 的首屏模块里，其他包无法取用：特性插件不得运行期导入另一个特性插件的值。

## Decision

ui-primitives 的 [`FishLogo`](../../../../packages/client/ui-primitives/README.zh.md) 新增 `swim` 属性。SMIL 让路径 `d` 在摆尾上、摆尾下两帧之间插值，同时一个 [CSS 模块](../../../../packages/client/ui-primitives/src/FishLogo.module.css) 以同一 1.6s 周期摆动整个标记，因此尾巴是真实曲线形变，而不是整体刚性旋转。两帧形变数据与静止路径并列放在 [fish-swim.ts](../../../../packages/client/ui-primitives/src/fish-swim.ts)；包的公开导出列表不变，未开启 `swim` 时渲染结果与之前完全一致，包括装配快照所固定的「没有 class 属性」这一点。

五个界面使用它，且每个界面只有一种加载表现：

- 首屏标记（`EmptyHero.tsx`）常驻游动。空白草稿首屏是落地页而非静止页，因此由标记承担页面自身的动效，而不是等悬停奖励；命中区保留不动的位置盒，但去掉指针事件。
- `settling` 相位（`ConversationContent.tsx`）在同一列里居中同一个标记，通过本地化的 `session.loading` 文案提供给辅助技术，不显示可见文字。它会通过 CSS（`:has(.viewArea)`）让位给已挂载的视图区，因此已经渲染视图的会话保留该视图自己的加载表现，同一区域不会出现两种加载样式。
- 聊天视图的历史回放提示在原有文字旁放一个 14px 标记，沿用该提示自身的三级墨色。
- 应用启动画面（`apps/web/index.html`）在任何脚本运行前就内联画出该标记，框架无关的启动页随后采纳这一屏：把进度环与提示填进预留的 `data-dsh-boot-status` 宿主，而不再自绘卡片，因此标记只画一次、不会被重画。UI 就绪时 React 挂载会整体替换该挂载点。
- 桌面闪屏窗口（`apps/desktop/renderer/splash.html`）在任何应用窗口存在之前、Host 启动期间显示该标记。欢迎窗口或主窗口一旦可见它就退出，致命启动报告会先撤下它，因此它绝不会比它所代表的界面活得更久。

两条通道都遵守「减少动态效果」：平台声明该偏好时渲染层不输出 SMIL 元素，样式表同时去掉摆动，因此在标记挂载期间改变的偏好同样能作用到动画上。

## Alternatives considered

**全局替换共享的 `StateDot` 进行中转圈。** 该圆点还承担转录行内的工具执行与步骤进度，品牌标记在那种行里会喧宾夺主；对 10–14px 的沟槽来说尺度也不对。本次改动限定在首屏与历史加载态。

**在 `FishLogo` 旁新增 `FishSwim` 组件。** 那会重复既有原语已经提供的 svg 结构、23.16:17.04 比例与 `currentColor` 墨色语义，违背包自身的复用规则：先扩展现有原语，再加平行组件。

**把形变数据留在 `ui-conversation`，复制一份到 `ui-chat`。** 客户端导出纪律禁止特性插件导入另一个特性插件的值，而且手抄的形变会与生成的版本漂移。共享运行期代码属于静态归属包，也就是 ui-primitives。

**让两个启动层直接导入这份几何，而不是各自持有美术。** 启动页必须在 React 到达之前就能工作，Electron 主进程也不应打包浏览器 UI 库，因此两者都无法导入该原语。于是两个启动画面各自持有在编写时由同一来源生成的静态美术——`renderer/assets/welcome-brand.svg` 已经为原生窗口记录了这一选择。代价是几何变化时这两份资产需要重新生成；收益是产品首屏完全不需要任何 bundle。

**用 CSS 的 `d` 属性做轮廓动画，让媒体查询在不写 JavaScript 的情况下接管减少动态效果。** CSS `d` 属性并未在本 GUI 需要支持的所有引擎中实现，而 SMIL 可以；本原语只保留一次带保护的探测。

**保留悬停作为首屏触发，只在加载界面加标记。** 悬停只对指针用户生效，而且恰好发生在最不缺注意力的界面上，与真正需要该信号的状态相反。

## Consequences

- 只要屏幕上是空白草稿，落地页就会持续播放动效；系统声明的「减少动态效果」是唯一的退出方式，且对形状与姿态两条通道都生效——包括两个启动画面：媒体查询够不到 SMIL，因此由一小段内联脚本移除它。
- 启动不再从空桌面或空白文档开始：闪屏窗口覆盖 Host 启动阶段，被服务的页面在首个脚本运行前就画出标记。
- 历史加载表现为产品自己的标记，而不再只是一行文字；settling 列也不会再闪出空白外壳。
- 游动目标（约 5.6 KB 路径数据）与摆动关键帧从 `ui-conversation` 迁入 `ui-primitives`；`EmptyHero.tsx` 因移出本地鱼组件而变短，`ui-conversation` 不再持有任何 SVG 曲线数据。
- 原语的减少动态效果分支、首屏回退、settling 标记与聊天提示均由 `pnpm run test:gui` 固定；侧边栏品牌标记的装配快照保持不变。
- 标记在首屏是装饰性的（对无障碍树隐藏），在 settling 列是有名称的 `status` 区域；聊天提示仍以原有文字作为可访问内容。
